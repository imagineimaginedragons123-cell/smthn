Q4. MAVEN CORE CONCEPTS
============================================================


1. pluginManagement vs plugins.
------------------------------------------------------------

pluginManagement:

<pluginManagement>
    <plugins>
        ...
    </plugins>
</pluginManagement>


It provides plugin configuration/defaults.

It does NOT normally activate the plugin by itself.


plugins:

<plugins>
    <plugin>
        ...
    </plugin>
</plugins>


This declares the plugin for use in the current build.


MEMORY:

pluginManagement = configuration/defaults

plugins = active plugin


------------------------------------------------------------
2. SNAPSHOT.
------------------------------------------------------------

Example:

<version>0.0.1-SNAPSHOT</version>


SNAPSHOT means the version is a development/unreleased
version.

It can change during development.

Release:

1.0.0

is intended to be a stable release.

Q8. DEPENDENCY ANALYSIS & SCOPE
============================================================


1. Detect unused dependencies.
------------------------------------------------------------

------------------------------------------------------------
2. Why is Servlet API scope provided?
------------------------------------------------------------

Example:

<dependency>
    <groupId>javax.servlet</groupId>
    <artifactId>javax.servlet-api</artifactId>
    <version>4.0.1</version>
    <scope>provided</scope>
</dependency>


The Servlet API is needed during compilation.

Tomcat supplies the Servlet API at runtime.

Therefore:

provided
= compile available, runtime supplied by container.


This avoids packaging the Servlet API unnecessarily
inside the application WAR.

If an incompatible Servlet API is packaged inside the WAR,
classloading/version conflicts may occur.

IMPORTANT GIT DIFFERENCES
============================================================

git diff
    Shows unstaged changes.

git diff --cached
    Shows staged changes.

git status
    Shows staged + unstaged + untracked files.

git restore file
    Discards uncommitted changes to file.

git restore --staged file
    Unstages file but keeps modifications.

git reset --soft HEAD~1
    Removes last commit but keeps changes staged.

git revert <commit>
    Creates a new commit undoing an old commit.
    Preferred for already-pushed/shared commits.

git fetch
    Downloads remote information without integrating it.

git pull
    Fetch + integrate remote changes.

git stash
    Temporarily saves uncommitted work.

git stash pop
    Restores and removes latest stash.

git merge
    Combines branch histories.

git rebase
    Replays feature commits on top of another branch.

git rebase --abort
    Cancels rebase.

git merge --abort
    Cancels merge.

============================================================
MOST IMPORTANT EXAM TRAPS
============================================================

1. git restore file

   DISCARDS uncommitted changes.


2. git restore --staged file

   ONLY removes file from staging.
   Changes are NOT deleted.


3. git reset --soft HEAD~1

   Removes last commit.
   Keeps changes staged.


4. git revert <commit>

   Safely reverses an already-pushed commit.
   Creates a new commit.


5. git fetch origin

   Downloads remote updates.
   Does not merge them.


6. git pull

   Fetches and integrates remote changes.


7. git rebase origin/main

   Moves/replays feature branch commits on latest main.


8. git rebase --abort

   Cancels a rebase.


9. git merge --abort

   Cancels a merge.


10. git rm --cached file

    Stops tracking file but keeps local copy.


11. .gitignore

    Prevents matching UNTRACKED files from being added.


12. Docker port syntax:

    -p HOST:CONTAINER


13. Example:

    -p 8080:8080

    means:

    HOST 8080 → CONTAINER 8080


14. Sports application Dockerfile requires:

    FROM openjdk:17-jdk-slim

    WORKDIR /app

    COPY target/sports-management.jar app.jar

    EXPOSE 8080

    CMD ["java", "-jar", "app.jar"]


15. Docker Hub image format:

    username/repository:tag


Example:

    yourusername/sportsapp:v1
